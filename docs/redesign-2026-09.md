## 动效和可访问性

按压 110ms、换题前后总计约 220ms、展开 300ms、进入 420ms、完成 560ms。前进与撤销采用相反方向；进入和结束使用更大空间变化。学习期间景观不出现、背景不运动。

评分在动画前同步保存；110ms 的输入锁在减少动态模式下仍保留，作用是防止重复事件。CSS 和 JavaScript 都遵循系统减少动态以及应用内设置，正在运行的 JS 动画会在偏好改变时结束。实现了对话框焦点约束、Escape 退出、固定评分区、动态视口和安全区处理；这些布局行为尚未经真实浏览器验收。

## 数据边界

- applyRating、createItem、normalizeItem、recomputeItem、mergeItems、syncLearningOsEvent 与基线逐段比较，内容未改变；历史 scheduleVersion 的回放语义保留。
- 题目 ID、source、history、排期及原有存储键保留，仍使用既有 Supabase 账号与 Edge Function。没有修改 jlpt.html、经典页、旧版资源或 Supabase 部署代码。
- 新增 eju.session.v1。先保存待提交事件的会话检查点，再保存题目；刷新恢复只接受确实存在的历史事件。恢复和评分前核对最新题目状态，过时或已经处理的题不会被再次评分。
- 上一题的撤销信息随会话恢复，并继续阻止该事件过早发往 Sheets。历史撤销仍用 removedReviewIds 防止旧云端记录回流。
- 新增 eju.itemRemovals.v1 和兼容摘要 eju.deletedItems.v1，记录本次录入撤销／导入替换产生的删除或显式恢复。它们随 JSON 备份和云端数据传递；有序修订确保显式备份恢复与旧副本不会互相反复覆盖。
- 导入使用 eju.dataTransaction.v1 作为跨键提交日志，避免题目、书目和删除标记在写入中断时不一致。兼容键未写完时，后续读取以日志为准。
- 导入“取消”只关闭界面；“替换”有单独影响范围和第二次确认，并明确说明不会删除 Sheets 已追加的行。
- 云同步失败不会被外层流程覆盖成成功。上传中有新的本机修改时显示待上传。读取本机最新数据时保留在途 Sheets 请求所引用的事件对象。

旧历史格式可继续导入和回放。旧版页面不理解新增的会话及删除／恢复字段；跨设备联动仍需在验收后使用一致版本。本 PR 不部署新版本。

## 运行

需要 Node.js 22 或更新版本。正式页面仍可直接由静态 HTTP 服务提供。

```bash
npm ci
npm test
npm start
```

npm start 启动 http://127.0.0.1:4173 。也可以沿用 python3 -m http.server 8000。

仅查看模拟数据：

```bash
npm run demo
```

打开 http://127.0.0.1:4174 选择正常题量、空状态、1000 道逾期题、长书名与长备注、本机保存失败或同步失败。模拟预览用专用 sessionStorage 命名空间代替应用的 localStorage，移除云端 SDK，刷新后仍可恢复当前标签页中的模拟会话。它不会读取真实学习数据或写入云端／Sheets。

若要在自己同一 Wi-Fi 的手机上测试，可运行 npm run demo -- --host=0.0.0.0 ，用电脑的局域网地址和端口 4174 打开。这是本地预览，并非线上发布。
